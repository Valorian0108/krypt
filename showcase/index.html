how it works

The agent asks. The contract answers.

1

Set limits in dollars.

A cap per purchase, an auto-approve limit, a budget per period, and the sellers you trust. The rules live in the vault, not in the agent's instructions.

2

Let the agent ask.

Small purchases pay themselves. Anything above the auto-approve limit waits for the owner. Anything above the cap, or to an unlisted seller, is refused before money moves.

3

Approve only what needs you.

One approval, one signature, and the receipt is written. Every outcome stays on chain: paid, waiting, refused, or failed.

run the full app

The owner flow stays local.

The hosted page can read and simulate. To sign in, set rules, approve a purchase, or refuse one, run the app on your machine.

  1. Clone the repo. Everything is public, including the contract and the tests.
  2. Run the contract tests. 45 tests cover caps, budgets, allowlists, approvals, and failures.
  3. Start the app. Copy app/env.example to app/.env and fill in a funded testnet sponsor. The README documents every variable.
  4. Open exactly http://localhost:3000. That origin is the only one the FastAuth testnet client allows.
